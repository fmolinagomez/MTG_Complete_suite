# Domain Glossary (CONTEXT.md)

This file defines the domain model and terminology for the MPCFillToPDF project to ensure consistent vocabulary across the codebase, tests, and documentation.

---

## 1. Core Concepts & Printing Pipeline

### Card (Carta)
An individual card in a trading card game (Magic: The Gathering, Lorcana, One Piece, Riftbound, etc.). A card contains:
- **Name**: The canonical name of the card.
- **Oracle ID**: Scryfall's canonical unique identifier across prints.
- **Set Code**: The three- or four-letter set code (e.g., `m21`, `ltr`).
- **Collector Number**: The specific print number within its set.
- **Quantity**: The number of copies of this card.

### Card Front & Card Back (Frente y Reverso)
- **Front**: The face of the card containing the artwork and game text.
- **Back**: The generic card back (e.g., default Magic backing) or a specific custom backing for double-faced cards.

### Bleed Area (Sangrado)
The extra outer margin on images intended for printing. Since MPC (MakePlayingCards) includes a bleed border, this tool crops it out (`4.2%` width and `3.1%` height per side) before placing cards in the PDF grid.

### Duplex Grid (Cuadrícula Dúplex)
A `3x3` layout on A4 portrait paper yielding `9` cards per page.
- **Front Pages**: Placed in standard slot order (0 to 8, left-to-right, top-to-bottom).
- **Back Pages**: Horizontally mirrored (slots `[2, 1, 0]`, `[5, 4, 3]`, `[8, 7, 6]`) so that duplex printing aligns fronts with their respective backs correctly.

## 2. Deck Importing & Scryfall Integration

### MtgUrlDeck / FetchedDeck
A deck definition parsed from external URLs (Moxfield, Archidekt, TappedOut, Manabox, etc.). It contains:
- **Mainboard (Mazo Principal)**: The core cards of the deck.
- **Sideboard (Banquillo)**: Additional cards for customization or format legality.
- **Tokens (Fichas)**: Extra accessory cards generated by mainboard cards.
- **Separator (Separador)**: An optional custom separator card inserted between decks during PDF compilation.

### Scryfall Quality Checker
A module that verifies Scryfall images for:
- **Minimum resolution**: Standard 300 DPI target (at least 745x1040 pixels).
- **Focus / Blurriness**: Uses a Laplacian variance check (`cv2.Laplacian`) to detect low-quality or blurry scans.

## 3. Moxfield & Deck Validator

### Technical Validation Status (Estados de Validación Técnica)
- 🟢 **Válido (Valid)**: The card exists on Scryfall and has high-resolution imagery available (`highres_image` is true in the API response).
- ⚠️ **Advertencia (Warning)**: The card was resolved by falling back to a name search (missing or invalid set/collector number in the deck), is a digital-only card, or lacks high-resolution imagery in Scryfall's database.
- 🔴 **Error (Error)**: The card could not be found on Scryfall, the API request failed, or no image URIs are available for either face.

### Card Preview & Tooltip Hover (Previsualización de Carta en Caché)
To optimize performance and bandwidth, the application downloads the `small` format image from Scryfall and caches it in `MPCFillToPDF/procesamiento/previews/`. When hovering over card rows in UI tables or selecting a card, a floating image tooltip displays the artwork instantly.

## 4. Card Inventory & Deck Binder System (Inventario y Mazos)

### Physical Card vs. Proxy (Carta Física vs. Proxy)
- **Physical Card (Carta Real/Física)**: A genuine physical card owned by the user in their collection (imported via ManaBox or added manually).
- **Proxy (Carta Proxy)**: A printed proxy or card representation registered in a deck or inventory (`is_proxy = True`).

### ManaBox CSV Import & Sync Modes (Importación de ManaBox)
ManaBox CSV exports are parsed to populate the inventory database. Two import synchronization modes are supported:
- **Replace (Sustituir)**: Wipes unassigned physical inventory and loads the new CSV export.
- **Merge (Combinar)**: Smart upsert that updates quantities, sets, and conditions while preserving existing deck assignments and historical proxy markers.

### Stock Allocation Strategy (Estrategia de Asignación de Stock - Opción C)
Tracks both `owned_quantity` and `assigned_quantity` across registered decks:
- Physical cards can be allocated to specific decks.
- If a card is required by multiple decks, the system calculates whether enough physical copies exist or marks the overflow as "Missing Proxies" to be printed.

### Missing Proxy Calculator & Deck Synchronization (Sincronización de Mazos y Proxies)
When analyzing an imported deck against the local inventory:
1. Compares deck cards against available physical stock.
2. Differentiates between:
   - **Exact Match (Stock Exacto)**: Matching `set_code` and `collector_number` available in collection.
   - **Alternative Print / Oracle Match (Stock Alternativo)**: Matching `oracle_id` or canonical name available in a different edition/art.
   - **Missing (Faltante / Proxy)**: No physical copies available in inventory; needs printing.
3. Automatically offers to generate a print-ready PDF containing **only the missing proxies**.
4. Automatically registers the deck and marks the newly queued cards as printed proxies for that deck.

### Card-to-Decks Usage Lookup (Consulta de Mazos por Carta)
Double-clicking or selecting any card in the collection opens a modal dialog (`CardDecksUsageDialog`) that cross-references all registered decks to display where that card is being utilized, the deck format, required quantity, and printing version.

### Advanced Collection Filtering & Smart Column Sorting (Filtros Avanzados y Ordenación)
- **Filters**: State of usage (all, available/unassigned, in-decks), set code (dynamically populated from inventory), rarity, and finishes (foil/proxy).
- **Sorting**: Column header toggle (▲/▼) with natural numeric sorting for quantities/numbers and case-insensitive alphabetical sorting for names/editions.

### Deck-to-Inventory Bulk Import (Volcado de Mazo a Inventario)
A feature allowing the user to import all cards from any registered deck directly into the permanent inventory, tagging them explicitly as either physical copies or proxies.

### Database Persistence (`inventario.db`)
Stored in SQLite at `MPCFillToPDF/inventario.db` (co-located with output and cache folders). Uses hybrid relational schema + JSON attributes for maximum query performance and extensible card metadata.
