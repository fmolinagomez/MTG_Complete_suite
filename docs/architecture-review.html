Candidate 01

Consolidate External Game Deck Scrapers into a Deep Deck Intake Module

Strong ports & adapters
Files: src/lorcana_scraper.py • src/op_scraper.py • src/rb_scraper.py • src/deck_importer.py • src/scryfall.py • gui/main.py

Problem

Four separate game scrapers duplicate downloading loops, thread pools, card expansion, and fallback back generation across shallow modules.

Solution

Unify game ingestion behind a single deep Deck Intake module with per-game parser adapters returning a canonical Deck model.

Candidate 03

Deepen Card Image Preparation behind Source Profiles

Worth exploring in-process
Files: src/cropper.py • src/pipeline.py • gui/locals_tab.py • cli/main.py

Problem

Boolean flags and crop dictionaries leak through four layers of modules to handle MPC bleed vs Scryfall corners vs local uploads.

Solution

Encapsulate image preparation recipes inside a deep Card Image Normalizer module parameterized by a declarative Source Profile.

(Fill Corners + Mirror)

(Mirror Only)

Callers supply raw card and declare profile. All cropping, corner sampling, luminance math, and mirror-bleed remain private implementation.

Architectural Wins

• Interface shrinks: deletes crop_map propagation
• Locality: image transforms concentrated together
• High leverage across all card sources
• Easy to add game-specific bleed profiles
• Tests target single transformation seam
Candidate 04

Consolidate Scryfall Resolution & Quality Assessment Seam

Worth exploring ports & adapters
Files: src/scryfall.py • src/quality.py • image_quality_analyzer.py • gui/moxfield_validator.py

Problem

Scryfall querying, quality filtering (Laplacian variance), and fallback prints leak across three separate modules and the validator GUI.

Solution

Deepen Scryfall interaction into a unified Scryfall Resolver module that encapsulates rate limiting, quality audits, fallback print searches, and preview caching.

ADR Alignment: Complements ADR-0001 (Moxfield Validator GUI) by cleanly separating Scryfall validation mechanics into a headless core module while keeping the Tkinter GUI lightweight.

Top Recommendation

Start with Candidate 01: Consolidate External Game Deck Scrapers

The four external card game scrapers (Lorcana, One Piece, Riftbound, and MTG/Scryfall) exhibit the highest duplication in the codebase—each re-implementing thread pools, card quantity expansions, fallback card backs, and error recovery. Deepening this into a unified Deck Intake module immediately reduces hundreds of lines of shallow boilerplate and establishes a clean seam that makes Candidate 02 significantly simpler to execute.
